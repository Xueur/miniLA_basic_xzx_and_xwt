# miniLA 流水线 SoC — 下板检查与关键模块详解

## 一、CoreMark 现场烧录

### 1.1 CPU 频率

`clk_wiz_0` PLL 将 `fpga_clk`（开发板晶振）倍频至 **50MHz**，输出 `pll_clk1`。

```verilog
// miniLA_SoC.v:17-31
wire sys_clk = pll_lock & pll_clk1;   // PLL锁定后才有时钟
reg  sys_rst;
always @(posedge fpga_clk) sys_rst <= !fpga_rst | !pll_lock;
```

**关键**: `pll_lock` 为低时 `sys_clk = 0`，CPU 不运行；PLL 锁定后时钟才有效。上板后 PLL 通常几百微秒内锁定。

CoreMark 代码中频率声明必须一致：

```c
// core_portme.c:36-37
#define MHZ 50
#define CLOCKS_PER_SEC (1000000 * MHZ)   // = 50,000,000
```

计时器 `io_peripherals.v` 里每周期 `timer <= timer + 1`，`get_time()` 读 `0xFFFF_4000`（低 32 位）和 `0xFFFF_4008`（高 32 位），拼成 64 位计数值。CoreMark 用 `CLOCKS_PER_SEC` 把 ticks 换算成秒，从而算分。

### 1.2 烧录步骤

```bash
# 1. 编译 CoreMark → 生成 main.coe
cd c_test/4_coremark
make

# 2. Vivado Tcl Console: 更新 BRAM IP 指向 CoreMark COE
set_property CONFIG.Coe_File "[pwd]/../c_test/4_coremark/main.coe" [get_ips bram_axi]
generate_target all [get_files src/rtl/ip/bram_axi/bram_axi.xci]

# 3. 合成 + 实现 + 生成 bitstream
reset_run impl_1
launch_runs impl_1 -to_step write_bitstream -jobs 16

# 4. 连接开发板并烧录
open_hw
connect_hw_server
open_hw_target
set_property PROGRAM.FILE [glob *.bit] [lindex [get_hw_devices] 0]
program_hw_devices [lindex [get_hw_devices] 0]
```

**注意**: 每次换测试程序（换 COE）必须重新 `generate_target` + `launch_runs`——BRAM 的初始值是在 bitstream 生成时嵌入的，不是在运行时加载的。

## 二、Cache 模块详解

DCache 和 ICache 结构完全对称，以下以 DCache 为主说明。

### 2.1 基本参数

| 参数 | 值 |
|------|-----|
| 组织 | 直连映射（Direct-mapped） |
| 容量 | 64 lines × 128 bits = **1KB** |
| Line 格式 | `{valid(1bit), tag(5bit), data(128bit)}` |
| 地址映射 | `Index = addr[9:4]` (6bit, 64 行), `Tag = addr[14:10]` (5bit), `Word = addr[3:2]` (2bit) |
| 写策略 | 写穿 (Write-through) + 写分配 (Write-allocate) |

### 2.2 核心设计：组合逻辑 `cpu_ren`/`cpu_wen`

与常见 CPU 设计最大不同：向总线发出的请求信号是**组合逻辑**，不是寄存器。

```verilog
// DCache.v:71-75
assign cpu_ren   = (state == ST_RD_REQ) ? 4'hF : 4'h0;     // 读：仅在 ST_RD_REQ 为1
assign cpu_raddr = {request_addr[31:4], 4'b0000};           // 读地址：组合逻辑
assign cpu_wen   = (state == ST_WR_REQ) ? request_wen : 4'h0; // 写：仅在 ST_WR_REQ 为1
assign cpu_waddr = request_addr;                             // 写地址：组合逻辑
assign cpu_wdata = request_wdata;                            // 写数据：组合逻辑
```

**为什么不用寄存器**: 寄存器保持 `cpu_ren` 会滞后状态变化。状态从 RD_REQ→RD_WAIT 后，`cpu_ren` 还残留 1 拍高电平，axi_bus 误以为有新请求，造成地址未更新的重复读。

### 2.3 状态机

**读路径**（3 个状态）:

```
IDLE ──(|data_ren && !cpu_hit)──→ RD_REQ ──(dev_rrdy)──→ RD_WAIT ──(dev_rvalid)──→ IDLE
  │                                    │
  └──(|data_ren && cpu_hit)────────────┘  (命中：直接返回，不离开 IDLE)
```

```verilog
// ST_IDLE: 命中直接返回数据，不离开当前状态
ST_IDLE: begin
    if (|data_ren) begin
        if (cpu_hit) begin
            data_rdata <= pick_word(lines[cpu_index], data_addr[3:2]);
            data_valid <= 1'b1;               // 1拍脉冲
        end else begin
            request_addr <= data_addr;
            state <= ST_RD_REQ;               // 缺失：进入 refill
        end
    end
end

// ST_RD_REQ: 发请求，等总线就绪
ST_RD_REQ:
    if (dev_rrdy) state <= ST_RD_WAIT;        // dev_rrdy=1 → 请求被总线接受
                                               // cpu_ren 下一拍变0

// ST_RD_WAIT: 等响应，到达当拍取数据回 IDLE
ST_RD_WAIT: begin
    if (dev_rvalid) begin
        lines[request_index] <= dev_rdata;     // 填充 cache line
        tags[request_index]  <= request_tag;
        valid[request_index] <= 1'b1;
        data_rdata <= pick_word(dev_rdata, request_addr[3:2]);
        data_valid <= 1'b1;
        state <= ST_IDLE;
    end
end
```

**写路径**（2 个状态）:

```
IDLE ──(|data_wen)──→ WR_REQ ──(dev_wrdy)──→ WR_WAIT ──(dev_wrdy)──→ IDLE
```

写穿策略：先发写请求到总线（WR_REQ），总线确认后进入 WR_WAIT 等写完成信号，最后置 `data_wresp=1` 通知 CPU。

### 2.4 命中判断

```verilog
// DCache.v:51-53 — 组合逻辑，1拍内完成
wire [5:0] cpu_index = data_addr[9:4];         // 6bit 索引
wire [4:0] cpu_tag   = data_addr[31:10];       // 5bit 标签
wire cpu_hit = valid[cpu_index] && tags[cpu_index] == cpu_tag;
```

全程组合逻辑——在 IDLE 态收到 `data_ren` 当拍就能判断命中，命中则当拍返回数据。未命中才进入状态机流。

### 2.5 `data_valid` 的 1 拍脉冲机制

```verilog
// 每个时钟周期默认清零
data_valid <= 1'b0;
data_wresp <= 1'b0;

// 仅在命中或 refill 完成时置1
case (state)
    ST_IDLE: if (|data_ren && cpu_hit) data_valid <= 1'b1;
    ST_RD_WAIT: if (dev_rvalid)        data_valid <= 1'b1;
endcase
```

**为什么必须是 1 拍脉冲**: 流水线通过 `daccess_rvalid = data_valid` 判断 load 是否完成。如果 `data_valid` 残留（状态切换后多 hold 1 拍），背靠背 load 的第二条指令进 EX/MEM 时会立即看到 `daccess_rvalid=1`，误判"数据已到"，用前一条 load 的数据完成写回。

### 2.6 ICache

完全相同的设计，只是仅有读路径（无写路径），连接 `inst_rreq`/`inst_addr`/`inst_valid`/`inst_out`。

## 三、ALU 模块详解

### 3.1 单周期运算

```verilog
// ALU.v:60-78 — 纯组合逻辑
always @(*) begin
    case (op)
        `ALU_ADD  : c = a + b;
        `ALU_SUB  : c = a - b;
        `ALU_AND  : c = a & b;
        `ALU_OR   : c = a | b;
        `ALU_XOR  : c = a ^ b;
        `ALU_SLL  : c = a << b[4:0];
        `ALU_SRL  : c = a >> b[4:0];
        `ALU_SRA  : c = $signed(a) >>> b[4:0];
        `ALU_SLT  : c = ($signed(a) < $signed(b)) ? 32'h1 : 32'h0;
        `ALU_SLTU : c = (a < b) ? 32'h1 : 32'h0;
        // ...
    endcase
end
```

### 3.2 乘除法：脉冲启动，杜绝重复触发

**核心设计**: 启动信号是**单拍脉冲**，不是电平。

```verilog
// ALU.v:18-22
wire start_mul  = md_start && ((op == `ALU_MUL) | (op == `ALU_MULH));
wire start_mulu = md_start && (op == `ALU_MULHU);
wire start_div  = md_start && ((op == `ALU_DIV) | (op == `ALU_MOD));
wire start_divu = md_start && ((op == `ALU_DIVU) | (op == `ALU_MODU));
```

`md_start` 来自流水线的 `mul_div_start` 信号：

```verilog
// cpu_core.v:194
wire mul_div_start = idex_valid && is_mul_div_ex && !idex_md_started;
```

**时序**: mul/div 指令首次进入 ID/EX 时 `idex_md_started = 0`，`mul_div_start = 1`（1 拍脉冲）。下一拍 `idex_md_started <= 1`，`mul_div_start = 0` 且永久不再为 1。乘除法器只启动一次。

**为什么不用电平**: 若 `start_mul = (op == ALU_MUL)`（电平触发），ID/EX 保持指令期间每拍都触发。必须用多层 gate（`started`、`md_started`、`busy_d1`）防重启。背靠背 mul 时 gate 清零的时序窗口恰好让 `start_mul` 用旧 operands 重新触发，导致第二、第三条 mul 的 `alu_c` 永远是第一条的结果。

### 3.3 operands 锁存

```verilog
// ALU.v:48-57
reg [31:0] md_a, md_b;
reg [ 4:0] md_op;

always @(posedge clk or posedge rst) begin
    if (rst) begin
        md_a  <= 32'h0; md_b <= 32'h0; md_op <= `ALU_ADD;
    end else if (md_start) begin
        md_a  <= a;      // 锁存被乘数/被除数
        md_b  <= b;      // 锁存乘数/除数
        md_op <= op;     // 锁存操作码
    end
end
```

乘除法需要 32 周期。期间流水线前进，`a`/`b` 变为下一条指令的 operands。锁存确保硬件模块在整个计算期间输入稳定。

### 3.4 输出选择

乘除法运行期间，`c` 读硬件模块输出：

```verilog
`ALU_MUL  : c = mul_res[31:0];       // Booth乘法器输出低32位
`ALU_MULH : c = mul_res[63:32];      // Booth乘法器输出高32位
`ALU_MULHU: c = mulu_res[63:32];     // 无符号乘法器输出高32位
`ALU_DIV  : c = div_quo_signed;      // 有符号商（含符号修正）
`ALU_DIVU : c = divu_quo[31:0];      // 无符号商
`ALU_MOD  : c = div_rem_signed;      // 有符号余数
`ALU_MODU : c = divu_rem[31:0];      // 无符号余数
```

`mul_res` 等来自硬件模块的 `z` 输出。当模块不是 `busy` 时，`z` 保持上一次计算结果，所以正确值一定在 `busy` 降 0 **之后**才能读取。

### 3.5 除法符号修正

```verilog
// ALU.v:41-46
wire div_neg_quo = md_a[31] ^ md_b[31];          // 被除数符号 ^ 除数符号
wire [31:0] div_quo_signed = div_neg_quo ?
    (~div_quo + 1'b1) : div_quo;                  // 负 → 取反加1
wire [31:0] div_rem_signed = md_a[31] ?
    (~div_rem + 1'b1) : div_rem;                  // 余数符号跟随被除数
```

硬件除法器 (`divider.v`) 对绝对值做运算，得到无符号商和余数。ALU 根据 `md_a[31]` 和 `md_b[31]` 做符号修正。`md_a`/`md_b` 是锁存值，确保在整个除法期间符号不变。

## 四、外设 I/O 连接详解

### 4.1 地址空间

| 外设 | 基地址 | 端口偏移 | 属性 | 功能 |
|------|--------|---------|------|------|
| 拨码开关 | `0xFFFF_0000` | 0x000 | 只读 | 16 位开关值 |
| LED | `0xFFFF_1000` | 0x000 | 只写 | 16 位 LED |
| 数码管 | `0xFFFF_2000` | 0x000 | 只写 | 32 位数值 |
| UART | `0xFFFF_3000` | 0x00 | 只读 | RX FIFO |
| | | 0x04 | 只写 | TX FIFO |
| | | 0x08 | 只读 | 状态寄存器 |
| | | 0x0C | 只写 | 控制寄存器 |
| 计时器 | `0xFFFF_4000` | 0x00 | 只读 | 64 位计数器低 32 位 |
| | | 0x08 | 只读 | 64 位计数器高 32 位 |

### 4.2 连接架构

外设**不走 AXI 总线**——在 SoC 顶层直接进行地址解码和请求拦截。

```
                       ┌─────────────────────────────┐
                       │       miniLA_SoC             │
                       │                              │
cpu_top ──AXI master──┼─┬──(io?)──→ io_peripherals ──┤ sw, led, rx, tx, 7seg
                       │ │           UART + Timer     │
                       │ │           + LED + Switch   │
                       │ │                            │
                       │ └──(!io)──→ bram_axi ── BRAM │
                       └─────────────────────────────┘
```

### 4.3 SoC 层地址解码

```verilog
// miniLA_SoC.v:191-192
wire io_read_req  = cpu_arvalid && cpu_araddr[31:16] == 16'hFFFF;
wire io_write_req = cpu_awvalid && cpu_awaddr[31:16] == 16'hFFFF;
```

**读地址通道**: 检查 `cpu_araddr[31:16] == 16'hFFFF`，同时 AR 有效（`cpu_arvalid=1`）。

**写地址通道**: 同样检查 AW 地址和 AW 有效。

### 4.4 BRAM 门控

```verilog
// miniLA_SoC.v:199-200
assign bram_awvalid = cpu_awvalid && !io_write_req;  // IO 写时关闭 BRAM AW
assign bram_arvalid = cpu_arvalid && !io_read_req;   // IO 读时关闭 BRAM AR
assign bram_wvalid  = cpu_wvalid && !io_write_req;   // IO 写时关闭 BRAM W
assign bram_rready  = cpu_rready && !io_read_req;    // IO 读时关闭 BRAM R
```

防止 IO 访问时 BRAM 看到不完整的 AXI 握手（如 `awvalid=0` 但 `wvalid=1`）。

### 4.5 响应 MUX

```verilog
// 读响应: IO 优先于 BRAM
assign cpu_rdata  = io_rvalid ? io_rdata  : bram_rdata;
assign cpu_rvalid = io_rvalid ? 1'b1      : bram_rvalid;
assign cpu_rlast  = io_rvalid ? 1'b1      : bram_rlast;

// 写响应: IO 优先于 BRAM
assign cpu_bresp  = io_wresp ? 2'b00      : bram_bresp;
assign cpu_bvalid = io_wresp ? 1'b1       : bram_bvalid;

// 就绪信号: IO 始终就绪（io_peripherals 单周期响应）
assign cpu_awready = io_write_req ? 1'b1  : bram_awready;
assign cpu_wready  = io_write_req ? 1'b1  : bram_wready;
assign cpu_arready = io_read_req  ? 1'b1  : bram_arready;
```

**关键**: `io_peripherals` 对每个 IO 请求都在 **1 个时钟周期** 内完成读写并返回 `io_rvalid`/`io_wresp`。所以 IO 访问时 CPU 的 ready 信号直接拉 1，不需要等待。

### 4.6 io_peripherals 内部逻辑

```verilog
// io_peripherals.v:67-135（简化）
always @(posedge clk or posedge rst) begin
    if (rst) begin
        timer <= 0; led <= 0; ...
    end else begin
        timer <= timer + 1'b1;     // 自由运行计时器
        io_rvalid <= 1'b0;         // 每拍默认清零
        io_wresp  <= 1'b0;

        // ---- 读 ----
        if (io_ren) begin
            io_rvalid <= 1'b1;
            case (io_addr)
                `PERI_ADDR_SWITCH:          io_rdata <= {16'h0, sw};
                `PERI_ADDR_UART + 32'h0:    io_rdata <= {24'h0, rx_data};        // RX FIFO
                `PERI_ADDR_UART + 32'h8:    io_rdata <= {28'h0, !tx_busy, ...};  // 状态寄存器
                `PERI_ADDR_TIMER + 32'h0:   io_rdata <= timer[31:0];              // 计时器低32
                `PERI_ADDR_TIMER + 32'h8:   io_rdata <= timer[63:32];             // 计时器高32
            endcase
        end

        // ---- 写 ----
        if (|io_wen) begin
            io_wresp <= 1'b1;
            case (io_addr)
                `PERI_ADDR_LED:             led <= merge_bytes(...);
                `PERI_ADDR_DIGLED:          dig_value <= merge_bytes(...);
                `PERI_ADDR_UART + 32'h4:    {tx_data, tx_start} <= ...;           // TX FIFO
                `PERI_ADDR_UART + 32'hC:    {rx_reset, tx_reset} <= ...;          // 控制寄存器
            endcase
        end
    end
end
```

**计时器**: 64 位自由运行计数器，CPU 频率 50MHz，溢出周期 = 2^64 / 50MHz ≈ 1.17 万年，远超 CoreMark 测试时间。

**UART**: `uart_simple.v` 提供 115200 波特率的 TX/RX。TX 有 `tx_busy` 状态信号，RX 有 `rx_valid` + `rx_pop` 握手。

## 五、AXI 总线详解

### 5.1 模块接口

`axi_bus.v` 一侧连接 ICache/DCache（4 个独立通道），另一侧是标准 AXI4 Master 接口（连接 bram_axi）。

| Cache 侧 | AXI4 侧 | 说明 |
|----------|---------|------|
| `ic_cpu_ren/raddr` | `m_axi_ar*` | ICache 读请求 |
| `dc_cpu_ren/raddr` | `m_axi_ar*` | DCache 读请求 |
| `dc_cpu_wen/waddr/wdata` | `m_axi_aw*` + `m_axi_w*` | DCache 写请求 |
| `dev2ic_rvalid/rdata` | `m_axi_r*` | 读响应 → ICache |
| `dev2dc_rvalid/rdata` | `m_axi_r*` | 读响应 → DCache |
| `dev2dc_wrdy` | `m_axi_b*` | 写完成 → DCache |

### 5.2 读写状态机

**读状态机**:

```
IDLE ──(dc_ren | ic_ren)──→ RADDR ──(arready)──→ RDATA ──(4-beat rvalid+rlast)──→ IDLE
```

**写状态机**:

```
IDLE ──(|dc_wen)──→ WRITE ──(awready && wready)──→ WRESP ──(bvalid)──→ IDLE
```

**优先级**: `dc_request = dc_cpu_ren || (|dc_cpu_wen)`，DCache 的读写优先于 ICache：

```verilog
// axi_bus.v:74-76
assign dc_dev_rrdy = state == ST_IDLE;               // DC 随时可用（IDLE 时）
assign dc_dev_wrdy = state == ST_IDLE;               // DC 写随时可用
assign ic_dev_rrdy = state == ST_IDLE && !dc_request; // IC 仅在 DC 无请求时可用
```

### 5.3 读操作完整代码路径

**Step 1 — IDLE: 捕获请求**

```verilog
ST_IDLE: begin
    if (|dc_cpu_wen) begin                     // 写请求
        write_addr <= dc_cpu_waddr; ...        // 锁存写地址/数据/strb
        state <= ST_WRITE;
    end else if (dc_cpu_ren) begin             // DCache 读请求
        read_addr  <= dc_cpu_raddr;            // 锁存读地址
        read_is_dc <= 1'b1;
        state <= ST_RADDR;
    end else if (ic_cpu_ren) begin             // ICache 读请求
        read_addr  <= ic_cpu_raddr;
        read_is_dc <= 1'b0;
        state <= ST_RADDR;
    end
end
```

**Step 2 — RADDR: 发送 AR 通道**

```verilog
ST_RADDR: begin
    if (m_axi_arready) begin                   // 从设备就绪
        read_beat  <= 2'h0;                    // beat 计数清零
        read_block <= 128'h0;                  // 数据缓冲区清零
        state <= ST_RDATA;
    end
end

// AXI AR 通道信号（组合逻辑）
assign m_axi_araddr  = {read_addr[31:4], 4'h0}; // 对齐到 128bit
assign m_axi_arlen   = 8'd3;                    // 4-beat burst (arlen=3)
assign m_axi_arsize  = 3'd2;                    // 4 bytes per beat
assign m_axi_arburst = 2'b01;                   // INCR
assign m_axi_arvalid = state == ST_RADDR;       // 仅在 RADDR 状态有效
```

**Step 3 — RDATA: 按 beat 接收数据**

```verilog
ST_RDATA: begin
    if (m_axi_rvalid) begin
        // 按 beat 编号存入 read_block 对应位置
        case (read_beat)
            2'd0: read_block[31:0]   <= m_axi_rdata;
            2'd1: read_block[63:32]  <= m_axi_rdata;
            2'd2: read_block[95:64]  <= m_axi_rdata;
            default: read_block[127:96] <= m_axi_rdata;
        endcase

        // 最后一拍: 拼装 128bit 并返回
        if (m_axi_rlast || read_beat == 2'd3) begin
            if (read_is_dc) begin
                dc_dev_rdata  <= {m_axi_rdata, read_block[95:0]};
                dc_dev_rvalid <= 1'b1;          // DCache 数据有效
            end else begin
                ic_dev_rdata  <= {m_axi_rdata, read_block[95:0]};
                ic_dev_rvalid <= 1'b1;          // ICache 数据有效
            end
            state <= ST_IDLE;
        end else begin
            read_beat <= read_beat + 1'b1;      // 下一 beat
        end
    end
end
```

**关键设计: `rdata` 对齐**:

```verilog
// rvalid 和 rdata 均为寄存器，同一拍更新，永远对齐
always @(posedge aclk) begin
    ic_dev_rvalid <= 1'b0;  // 默认清零
    dc_dev_rvalid <= 1'b0;
    if (...m_axi_rvalid && m_axi_rlast...) begin
        dc_dev_rdata  <= {m_axi_rdata, read_block[95:0]};
        dc_dev_rvalid <= 1'b1;  // rvalid 和 rdata 同一 NBA
    end
end
```

这是修复的关键：旧版 axi_bus 中 `rvalid` 是组合逻辑（`always @(*)`）、`rdata` 是寄存器，相差 1 拍。DCache 在 `rvalid=1` 时读到旧 `rdata`。现在两者同一拍更新，绝不对齐出错。

### 5.4 Uncached 写和读

当前设计中，**所有内存访问都走 Cache**。`0xFFFF_xxxx` 外设地址在 SoC 层被拦截，根本不经过 AXI 总线，所以不需要 cache/uncache 判断。

**为什么写不需要 uncached 特殊处理**:

写穿策略（write-through）下，写操作的行为本来就简单：

1. 写命中 → 更新 Cache line + 发出总线写请求
2. 写缺失 → 直接发出总线写请求（写分配：会先 refill 再写，但 DCache 当前实现简化了这步）

不管是 cached 地址还是 uncached 地址，写操作最终都是发 AXI 写请求到 BRAM。没有"cached 写需要 merge、uncached 写需要 bypass"的区别——这是读路径才有的问题。

**为什么读需要 uncached 处理（如果需要的话）**:

读操作在 cached 和 uncached 下的区别很大：

- **Cached 读**: 查 Cache → 命中直接返回 → 缺失 refill（4-beat burst 填整个 line）
- **Uncached 读**: 不能用 Cache line 的数据（可能是旧数据），必须**每次**都发单 beat AXI 读请求，而且不能填充 Cache line（否则下次读到旧值）

如果将来需要访问 DDR（`0x2000_0000`）或其他非外设、非 BRAM 的地址，需要在 DCache 的 IDLE 态加上 `is_io`（或 `is_uncached`）判断，类似：

```verilog
if (cpu_hit && !is_uncached) begin
    // Cached hit: 直接返回
end else if (is_uncached) begin
    // Uncached: 发单 beat 读请求, 不填 Cache line
    state <= ST_RD_REQ;
    // 但 arlen=0 (单 beat), 且不更新 valid/tags/lines
end else begin
    // Cached miss: 正常 refill
end
```

## 六、关键设计决策总结

| 设计点 | 选择 | 原因 |
|--------|------|------|
| Cache `cpu_ren` | 组合逻辑 | 寄存器会滞后状态变化，导致重复请求 |
| Cache `data_valid` | 默认清零，1拍脉冲 | 防止背靠背 load 误完成 |
| ALU 乘除法启动 | 单拍脉冲 `md_start` | 电平触发导致背靠背 mul 重复启动，结果错 |
| ALU operands | `md_a`/`md_b` 锁存 | 多周期期间 `a`/`b` 随流水线变化 |
| 外设连接 | SoC 层地址解码 | 不走 AXI 总线，简化设计 |
| `rvalid`/`rdata` 对齐 | 同拍寄存器更新 | 组合 `rvalid` + 寄存器 `rdata` 差1拍 |
| `mem_done` guard | `daccess_rvalid && mem_req_sent` | 未发请求时不接受响应，防假完成 |
| `exmem_just_changed` | 延迟1拍发 `daccess_ren` | 新指令进 EX/MEM 后地址未稳定 |
| `mul_div_start` | `idex_valid && is_mul_div_ex && !idex_md_started` | 仅在新指令首拍发一次脉冲 |
